# Repository Guidelines

## Project Structure & Module Organization
SayMore is a WinForms client targeting .NET Framework 4.8. Application code lives in `src/SayMore`, organized by feature folders such as `Model`, `UI`, `Utilities`, and `Transcription`. NUnit fixtures live in `src/SayMoreTests` and mirror the production namespaces; use categories like `SkipOnCI` for tests that can't run on CI (e.g. interactive tests or ones needing tooling unavailable on build agents). Packaging assets sit in `src/Installer` (WiX), while `build/SayMore.proj` drives CI builds and version stamping. Supporting material is stored under `DistFiles` (release notes), `SampleData` (demo content), `artwork` (branding), and `AutoSegmenter` for native helpers. SayMore uses **Autofac** for dependency injection; follow existing registration and lifetime patterns, update registrations when adding constructor dependencies, and avoid bypassing DI with manual instantiation without explicit justification.

## Build, Test, and Development Commands
Run `nuget restore SayMore.sln` after cloning to hydrate release tasks and third-party assemblies. Use `msbuild SayMore.sln /p:Configuration=Debug /m` for daily work; binaries land in `output/x64/Debug/net48/`. Execute `nunit3-console output/x64/Debug/net48/SayMoreTests.dll --where "cat != SkipOnCI"` to match CI. `.github/workflows/build-test-installer-release.yml` builds, tests, and produces a signed installer on tag pushes; full release publishing isn't wired into GitHub Actions yet, though there's no intention of continuing to publish via TeamCity. For a local, unsigned test build of the installer, `cd build` and run `TestInstallerBuild.bat` from there — its restore and MSBuild commands use `..\`-relative paths that assume that working directory.

## Coding Style & Naming Conventions
The root `.editorconfig` enforces tab indentation for `.cs` files; keep braces on new lines in the Visual Studio default style. Stick to PascalCase for types and public members, `_camelCase` for fields, and camelCase locals. Place shared UI controls under the closest `UI/*` folder, and extend existing helpers in `SayMore.Utilities` or `SIL.*` libs before adding new infrastructure. SayMore uses **L10NSharp** for localization: WinForms UI strings are localized via `L10NSharpExtender` entries in designer files (e.g. `SetLocalizingId`, `LocalizationPriority`). Do not move UI strings into `Resources.resx`, and do not remove or refactor localization extender code in `.Designer.cs` files.

## Testing Guidelines
Tests target NUnit 3; annotate fixtures with `[TestFixture]` and name them `<ClassName>Tests`. Express methods as `Method_State_Result` and co-locate helper builders in `SayMoreTests.Utilities`. Tag UI or intermittent tests, or ones needing tooling unavailable on CI agents, with `[Category("SkipOnCI")]` so CI filters them automatically. When adding sample files, drop them into `SayMoreTests/Resources` and embed via the generated designer.

## Commit & Pull Request Guidelines
Write imperative, single-sentence commit subjects and reference related JIRA keys (`SP-1234`) when known. Keep logical changes isolated per commit or PR. Bundle installer changes only when they're required by the application change (e.g. new dependencies or data files); avoid mixing unrelated installer refactors or packaging changes with application logic. Update `DistFiles/releasenotes.md` for any user-facing change. Pull requests should summarise motivation, list automated/manual test results, and attach screenshots or sample projects for UI-facing changes. Note the CI checks on your PR and call out any categories you excluded locally. Request a review and note follow-up tasks in the PR body.
